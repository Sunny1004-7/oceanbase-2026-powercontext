组会之后，常见的三种断线

“上次决定是什么来着？”

结论散落在群聊第 200 条消息里，翻半天找不到，只好再讨论一遍。

“这周谁在做什么？”

任务口头分配，没有状态和截止日期，下次组会才发现同一件事没人动。

“交接全靠口述”

有人毕业或退出，接手的人拿不到完整脉络，周报也说不清依据来自哪次记录。

组会接力不替你开会，也不猜你的意思——它只负责把写下来的东西可靠地接住、连上、传下去。

三步接力：记录 → 接续 → 交接

  1. 1

    记录

    按模板导入 Markdown / CSV 复盘，或直接填表单：已完成、困难、决定、下一步四项，加上带负责人和截止日期的任务表。重复导入不会产生重复任务。

  2. 2

    接续

    下次打开，首页给出「从这里继续」卡片：未完成任务、最近的决定、上次留下的下一步。完成或编辑任务，写错的记录可以修正或撤回。

  3. 3

    交接

    生成周报或交接单，每条内容标注来源记录编号，可回看原始输入。称呼、输出重点等偏好会体现在报告里。复制或下载 Markdown 即可发出。

手绘示意 · 记录可以被纠正，历史仍然可查

  1. 周一 导入 week-1 复盘有效
  2. 周三 发现盐度写错，提交修正版本week-1 → 新版本
  3. 周五 周报只汇总有效记录，旧版本仍可追溯来源可查

已实现的功能，与明确的边界

能做当前版本已实现

  • 约定格式输入：结构化 Markdown / CSV 导入，字段校验、去重
  • 任务管理：稳定 ID、状态流转、负责人、截止日期，可完成与编辑
  • 四项复盘：已完成 / 困难 / 决定 / 下一步，支持多行文本
  • 项目隔离：每个项目独立存储范围，互不串数据
  • 来源追溯：报告内容可回指具体记录与原始输入
  • 修正与撤回：错误记录出新版本或标记无效，历史保留
  • 偏好影响报告：称呼、输出重点持久化并用于生成
  • 带来源的周报 / 交接单，Markdown 复制与下载

范围适用条件

  • 任意会议全文理解：不做智能摘要，不按自然语言猜测字段
  • 云端多人协作：单机单进程、单用户设计，无登录系统
  • LLM 依赖：不需要模型 API，也不需要额外注册账号

适合个人或小组在单机上整理约定格式的项目进展；报告依据当前有效记录生成。

它是怎么记住的：PowerContext + 分工

像记账一样记事件

应用不直接改一张「当前状态表」。每次导入、完成任务、修正记录，都作为一条不可变事件写进 PowerContext（SDK 内置 SQLite）。要显示当前状态时，按 SDK 的分页接口把事件读回来，重放出「现在有效的记录」：被修正的旧版本、被撤回的记录不再计入，但随时能查。

这样即使换个进程重新打开，读到的仍是同一份有效状态；浏览器只缓存「当前选中项目」这类界面偏好，业务数据不落浏览器。

谁做了什么

  • Qoder CN CLI 1.1.81：主要业务逻辑、界面与 PowerContext 接入的开发。
  • Codex：规格与环境、独立测试、发布核验与材料整理。
  • 本展示站：由 Qoder 制作的静态入口，仅介绍与引流，不连接任何本地数据。

运行时：Python 3.12 · FastAPI 0.115.14 · PowerContext 1.4.1（builtin SQLite）

三步启动（Linux / WSL，Python 3.12+）

  1. 获取固定版本代码并进入目录

    git clone https://github.com/Sunny1004-7/oceanbase-2026-powercontext.git
cd oceanbase-2026-powercontext
git checkout {{SOURCE_SHA}}
cd qoder

  2. 安装依赖

    bash scripts/setup.sh

  3. 启动，浏览器访问本机地址

    bash scripts/start.sh
# 服务地址 http://127.0.0.1:4323（仅本机）
