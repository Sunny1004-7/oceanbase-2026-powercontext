# E04 一页技术说明

**模型与端侧运行。** Transformers.js **3.8.1** 在浏览器 Dedicated Worker 内执行文档与查询 embedding。固定 `Xenova/bge-small-zh-v1.5@75c43b069aac4d136ba6bc1122f995fedcfd2781`，CLS 池化、L2 归一化、512 维、最大 512 tokens；查询前缀为“为这个句子生成表示以用于检索相关文章：”。MIT 来源和上游卡片见 manifest/provenance/licenses。采用公开 FP16/INT8 ONNX 文件，未自行转换。按同一口径计入 ONNX 与共同 tokenizer/config：FP32 **95,401,750 B**，FP16 **48,047,300 B**，INT8 **24,560,715 B**；压缩比分别 **1.9856× / 3.8843×**，每个文件均测量字节与 SHA-256。

**后端与状态。** 默认显式请求 WebGPU/FP16；缺少 GPU、无适配器或初始化异常时自动降级 WASM/INT8，界面显示实际后端与降级标记。固定模型身份和查询规则参与集合身份，不跨方案混用向量。浏览器缓存下载文件，同一 Worker 复用模型。真实 Windows Chrome **156.0.8078.74**、RTX 4060 Laptop GPU（NVIDIA Lovelace，`isFallbackAdapter=false`）完成全流程；禁用 Chrome GPU 和软件光栅化后，`auto` 实际因“未找到可用 GPU”降级，并完成同样全流程。所有资产由本地服务提供，测试期间阻止外部网络；网络记录、Worker URL 与适配器信息均保存。

**seekdb。** Node **22.14.0** + seekdb-js **1.4.0** 接入官方预编译 seekdb **1.4.0.0**（`pylibseekdb 1.4.0.post2` 打包 server）。显式 `embeddingFunction:null`，浏览器提交 ID、原文、元数据与向量；SDK 建全文/向量索引。`hybridSearch` 经 `GET_SQL` 取得含全文条件、向量条件与 RRF 的 SQL 并在数据库执行，未在应用端合并排名。`refresh_index()` 后有界核对原文可见性；实际验证增量写入、相同 ID 更新、独立集合切换、连续查询及重启。输入错误与空结果有明确提示。

**实测。** 同一设备、50 篇原创中文笔记、20 条冻结查询；每种方案完整导入 3 次，热查询 100 次，取中位数。下表中模型加载是新浏览器首次初始化，热查询不含先前模型加载；端到端计至结果 DOM 与同步布局就绪。

| 配置 | 首次加载 ms | 文档推理 50 篇 ms | 查询推理 ms | seekdb ms | 端到端 ms | Recall@5 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| FP32 / WASM | 2417.78 | 1824.41 | 25.93 | 5.56 | 36.96 | 0.95 |
| FP16 / WebGPU | 3070.38 | 512.97 | 15.96 | 5.42 | 30.85 | 0.95 |
| INT8 / WASM | 1060.35 | 1418.90 | 42.86 | 6.01 | 58.89 | 0.95 |
| 自动降级 INT8 / WASM | 1064.87 | 1216.32 | 19.61 | 5.78 | 30.54 | 0.95 |

同口径 ONNX 本地下载耗时分别为 FP32 **1609.17 ms**、FP16 **995.59 ms**、INT8 **408.97 ms**；总加载包含 tokenizer 与会话初始化。写入中位数依次为 **237.49 / 329.88 / 206.62 / 211.05 ms**，刷新与可见性为 **629.14 / 618.72 / 513.19 / 527.45 ms**。GPU/FP16 只改变 batch size 的三次全量对照：batch=1 为 **1056.72 ms**，batch=4 为 **512.97 ms**，本次约 **2.06×**；测试顺序固定，未随机化。量化质量下降为 **0**。INT8 在手动 WASM 热查询中未比 FP32 更快，不声称全面加速。GPU/FP16 与 WASM/INT8 是后端和精度联合比较，不能只归因于 GPU。

**范围与证据。** 初始原问句全文条件 Recall@5=0.75，改为通用中文停用表达清理与术语扩展后为 0.95；模型的语义查询仍使用原问句。未更改语料、查询或相关集合；保留两条只召回一篇的难例。内部目标 0.85、下降不超过 0.05 已达到，非官方阈值；本集参与了调试。原始 CSV/JSON/网络/SQL、干净启动与重启记录全部交付，无估计值。默认一批不超过 100 篇，每篇原文不超过 10000 字；长于模型窗口会截断向量输入，全文仍完整保存。以上为本地验收，不代表官方得分。

最终增加了 API 操作排队，保证 SDK 会话变量在并发调用时不相互覆盖，并丢弃切库状态请求的迟到回复。现场浏览器生成向量的 16 个并发检索及受控乱序状态回复专项回归通过（`evidence/concurrency.json`）。上表为父候选 `024343144491b2d69820f0dfab1187a05bbed4f2` 的完整顺序请求实测；最终修复保持模型、语料、查询规则与数据库融合算法不变，并发排队时不套用表中的顺序请求延迟。
